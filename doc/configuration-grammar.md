# Server Configuration Guide

This document outlines the structure, syntax, and available directives for configuring the web server. The configuration file uses a declarative, block-based structure similar to NGINX.

## ⚠️ Important Syntax Rule: Strict Space Separation

To ensure the parser reads the configuration correctly, **every single token must be separated by whitespace (includes `std::isspace(c) == true`, i.e. `"\t\n\v\f\r"` and `' '`)**.

This includes keywords, paths, and punctuation marks like semicolons `;` and braces `{` `}`.

* ❌ **Incorrect:** `listen 8080;` (Semicolon is attached to the port)
* ✅ **Correct:** `listen 8080 ;`
* ❌ **Incorrect:** `location / {autoindex` or `location /{` (Missing spaces)
* ✅ **Correct:** `location / { autoindex` or `location / {`\n`autoindex`

Lines beginning with `#` are treated as comments.

## 1. Global / Server Directives

These directives reside at the top level of the configuration file and define the core behavior of the server.

* **`listen`**
Binds the server to a specific address and port.
* *Usage:* `listen <address_and_port> ;` (e.g., `listen 8080 ;` or `listen 127.0.0.1:8080 ;`)


* **`error_page`**
Defines a custom HTML file to serve for a specific HTTP error code.
* *Usage:* `error_page <status_code> <file_path> ;` (e.g., `error_page 403 ./www/err/403.html ;`)


* **`root`**
Sets the root directory for requests.
* *Usage:* `root <path> ;` (e.g., `root ./www ;`)


* **`client_max_body_size`**
Sets the maximum allowed size of the client request body.
* *Usage:* `client_max_body_size <size> ;` (e.g., `client_max_body_size 1 ;`)



## 2. Location Context

The `location` directive creates a block that applies specific configurations to URLs matching a given path.

* **`location`**
* *Usage:* `location <path> { ... }`



### Directives Allowed Inside `<location>`:

* **`allowed_methods`**
Restricts which HTTP methods are permitted for this location.
* *Usage:* `allowed_methods <method> [ <method> ... ] ;` (e.g., `allowed_methods GET POST DELETE ;`)


* **`autoindex`**
Enables or disables directory listing when no index file is found.
* *Usage:* `autoindex < "on" | "off" > ;` (e.g., `autoindex on ;`)


* **`index`**
Defines the default file to serve when a directory is requested.
* *Usage:* `index <file_path> ;` (e.g., `index /res/html/index.html ;`)


* **`upload`**
Specifies the directory where uploaded files should be saved.
* *Usage:* `upload <path> ;` (e.g., `upload ./www/upl ;`)


* **`alias`**
Replaces the location path with a specific directory path (different from `root` which appends).
* *Usage:* `alias <path> ;` (e.g., `alias /img ;`)


* **`return`**
Performs an HTTP redirection.
* *Usage:* `return <status_code> <redirect_url> ;` (e.g., `return 301 /new-page.html ;`)


* **`cgi_path`**
Defines the absolute paths to the CGI executable binaries.
* *Usage:* `cgi_path <path> [ <path> ... ] ;` (e.g., `cgi_path /usr/bin/python3 /usr/bin/php ;`)


* **`cgi_ext`**
Defines the file extensions that should trigger the CGI execution corresponding to `cgi_path`.
* *Usage:* `cgi_ext <extension> [ <extension> ... ] ;` (e.g., `cgi_ext .py .php ;`)

## 3. Formal Grammar (EBNF)

The following EBNF (Extended Backus-Naur Form) describes the exact structural specification of the configuration file. It stops at the token level (basic types like `<path>` and `<number>` are generated by the lexical analyzer).

```ebnf
<configuration> = { <server_directive> | <location_block> } ;

(* --- Block Definitions --- *)
<location_block> = "location" , <path> , "{" , { <location_directive> } , "}" ;

(* --- Directive Categories --- *)
<server_directive> = <listen_directive> 
                   | <error_page_directive> 
                   | <root_directive> 
                   | <client_max_body_directive> ;

<location_directive> = <root_directive>
                     | <allowed_methods_directive>
                     | <autoindex_directive>
                     | <index_directive>
                     | <upload_directive>
                     | <alias_directive>
                     | <return_directive>
                     | <cgi_path_directive>
                     | <cgi_ext_directive> ;

(* --- Server Directives --- *)
<listen_directive>          = "listen" , <address_port> , ";" ;
<error_page_directive>      = "error_page" , <status_code> , <path> , ";" ;
<client_max_body_directive> = "client_max_body_size" , <number> , ";" ;

(* --- Location / Shared Directives --- *)
<root_directive>            = "root" , <path> , ";" ;
<allowed_methods_directive> = "allowed_methods" , <method> , { <method> } , ";" ;
<autoindex_directive>       = "autoindex" , ( "on" | "off" ) , ";" ;
<index_directive>           = "index" , <path> , ";" ;
<upload_directive>          = "upload" , <path> , ";" ;
<alias_directive>           = "alias" , <path> , ";" ;
<return_directive>          = "return" , <status_code> , <url_or_text> , ";" ;
<cgi_path_directive>        = "cgi_path" , <path> , { <path> } , ";" ;
<cgi_ext_directive>         = "cgi_ext" , <extension> , { <extension> } , ";" ;

(* --- Base Tokens (Generated by the Lexer) --- *)
(* Note: All tokens implicitly require surrounding whitespace to be recognized *)
<address_port> = ? Valid IP/port string e.g., "8080" or "127.0.0.1:80" ? ;
<path>         = ? Valid file or directory path ? ;
<number>       = ? Numeric integer string ? ;
<status_code>  = ? 3-digit HTTP status code ? ;
<method>       = ? HTTP method e.g., "GET", "POST" ? ;
<extension>    = ? File extension e.g., ".py", ".php" ? ;
<url_or_text>  = ? Valid URL or redirect string ? ;

```
