# Directory Naming

## Root Directory (General IT / Development)

- **`/bin`**: The binaries directory. This contains the final compiled, executable files that run the application. Once the source code is compiled by the compiler and linked, the resulting ready-to-run program lives here.
- **`/doc`**: The documentation directory. This holds all the explanatory materials for the project, such as API references, architecture diagrams, user manuals, and readmes, keeping text-based guides separate from the code.
- **`/inc`**: The includes directory. Common in C and C++ projects, this holds the header files (like `.hpp` or `.h`). These files contain declarations for functions, classes, and macros that are shared and "included" across multiple source code files.
- **`/log`**: The logs directory. This contains log files that record runtime events, errors, access requests, and system diagnostics. It is crucial for debugging and monitoring the health of the application while it is running.
- **`/obj`**: The objects directory. This stores intermediate, unlinked object files (usually `.o` files) generated by the compiler from the source code. Keeping them here prevents the source directory from getting cluttered during the build process.
- **`/tst`**: The tests directory. This contains automated testing code, such as unit tests, integration tests, and test-case data. It is isolated from the main source code so that testing frameworks can run without bundling tests into the final production build.
- **`/cfg`**: The configuration directory. This holds configuration files (like `.conf`, `.ini`, or `.env`) that define operational parameters for the software, allowing users to change how the program behaves without having to recompile the code.
- **`/img`**: The images directory. At the root level, this usually stores visual assets related to the project repository itself, such as diagrams for the documentation, architecture flowcharts, or a logo for the README file.
- **`/src`**: The source directory. This is the heart of the project. It contains the actual source code files (like `.cpp` or `.c` files) where the developer writes the core logic and functionality of the application.
- **`/www`**: The World Wide Web directory (often called the document root). This is the public-facing folder that contains the content intended to be served over the network to a client's web browser.

## Inside the `/www` Directory (Web Server Specific)

- **`/res`**: The resources directory. This holds the static web assets required to style and add client-side functionality to the web pages. It typically contains CSS stylesheets, frontend JavaScript files, fonts, and sometimes downloadable media.
- **`/err`**: The errors directory. This is used to store custom HTML error pages (e.g., `404.html` for "Not Found", or `500.html` for "Internal Server Error"). The web server is configured to pull pages from this folder when a specific HTTP error code is triggered.
- **`/img`**: The images directory (web context). Unlike the root `/img` folder, this one holds the visual assets specifically meant to be served to the public website, such as photos, icons, graphics, and SVGs that appear on the web pages.
- **`/cgi`**: The Common Gateway Interface directory. This folder acts as a bridge between the web server and backend executable scripts (in this case, Python or PHP). When a client requests a dynamic resource, the web server executes a script in this directory, which generates HTML on the fly and passes it back to the client.
